# POS ร้าน โคตร เทพ — เวอร์ชัน 3.7

Google Sheets เป็นฐานข้อมูล, Google Apps Script เป็น API, GitHub เก็บซอร์สโค้ด และ Netlify เผยแพร่หน้าเว็บจาก `public/` ร้านแต่ละแห่งต้องใช้ Google Sheets, Apps Script และ Netlify site แยกกัน

รุ่น ZIP นี้ลดจำนวนครั้งที่ Apps Script เรียกอ่าน Google Sheets ต่อชีต และข้ามการอ่านรายการจองสินค้าเมื่อไม่มีใบเสนอราคาที่จองอยู่ เพื่อให้การเปิดหน้าและโหลดรายการเร็วขึ้น

## สิ่งที่เพิ่มและแก้ในรุ่นนี้

- เมนูซื้อสินค้า: พิมพ์ค้นหาด้วยชื่อ รหัส บาร์โค้ด หมวด หรือตำแหน่ง และสแกนบาร์โค้ดแล้วกด Enter ได้
- ลดการอ่าน Google Sheets ซ้ำภายในคำขอ API เดียวกัน และโหลดข้อมูลลูกหนี้/เจ้าหนี้ที่ไม่ขึ้นต่อกันพร้อมกัน

- ตั้งขนาดใบเสร็จ/ใบแจ้งหนี้เป็น A4 หรือ 80 มม. ที่เมนูตั้งค่า; ใบเสนอราคาและใบรายการตำแหน่งสินค้าใช้ A4
- เก็บชั้น/ตำแหน่งของสินค้า แสดงในหน้าและเอกสาร และพิมพ์รายการตำแหน่งได้
- เปิดใบเสนอราคาแบบจองหรือไม่จองสินค้า กำหนดวันหมดอายุ ยกเลิก และแปลงเป็นขายเชื่อ (Invoice) หรือขายสด/โอน (Receipt)
- ยอดจองจากใบเสนอราคาที่เปิดอยู่และยังไม่หมดอายุหักออกจากจำนวนที่ขายได้
- รายงานเลือกวันนี้ เดือนนี้ เดือนที่แล้ว ปีนี้ ปีที่แล้ว หรือวันที่เอง; Owner/แอดมินดาวน์โหลด Excel `.xlsx` และ PDF ได้
- Owner เท่านั้นที่ตั้งเพดานส่วนลด ใช้ PIN Owner อนุมัติรายการที่เกินเพดาน รวมถึงสำรองข้อมูล Archive และ Factory Reset
- Admin/Owner เปลี่ยนชื่อร้านและเลือก VAT Inclusive หรือ VAT Exclusive ได้
- เปิด/ปิดการแสดงสินค้าที่เคยขายได้ โดยเก็บประวัติและยอดคงเหลือไว้
- ป้องกันการบันทึกบิลขายซ้ำด้วย `requestId`; ราคาขายตรวจจากข้อมูลสินค้าฝั่ง API
- ใบลดหนี้คืนสินค้าใช้ราคาขายสุทธิที่ลูกค้าจ่าย รวมส่วนลดท้ายบิลและ VAT ตามสัดส่วน
- คืนเงินสดและยกเลิกบิลเงินสดลงกะปัจจุบันและตรวจเงินคงเหลือก่อนบันทึก
- สำรอง Google Spreadsheet ทั้งไฟล์ก่อน Archive/Reset; Archive เฉพาะธุรกรรมที่ปิดแล้วก่อนวันที่เลือก และทำยอดยกมาของ StockMoves

## อัปเดตจากเวอร์ชัน 3.6

1. สำรอง Google Spreadsheet และเก็บ ZIP รุ่นเดิมไว้ก่อนอัปเดต
2. ใน Apps Script ให้แทนที่ไฟล์ `.gs` เดิมทั้งหมดด้วยไฟล์ใน `apps-script/` และเพิ่มไฟล์ใหม่ `Quotations.gs` กับ `DataManagement.gs`
3. รัน `setupAll()` หนึ่งครั้งเพื่อเพิ่มชีต/คอลัมน์/ตัวนับใหม่โดยไม่ลบข้อมูลเดิม รวมถึงคอลัมน์ `request_id` ของบิลซื้อ และสร้างล็อตยกมาสำหรับสินค้าที่มีจำนวนแต่ยังไม่มีล็อต
4. หากมีแอดมินรุ่นเดิม ระบบจะย้ายแอดมินที่ใช้งานอยู่คนแรกเป็น Owner และบังคับเปลี่ยน PIN เมื่อเข้าระบบ หากยังใช้ PIN เริ่มต้น `1234` ระบบจะเปลี่ยนเป็น PIN ชั่วคราวใหม่และแสดงใน Execution log ของ `setupAll()` หากเป็นฐานข้อมูลใหม่ ระบบสร้าง Owner `U001` พร้อม PIN ชั่วคราว 6 หลักใน log เดียวกัน
5. Deploy Apps Script เป็น **เวอร์ชันใหม่** เพื่อให้ API ใหม่ทำงาน; URL `/exec` เดิมใช้ต่อได้
6. ใน GitHub repository ของร้านนี้ ให้วาง **เนื้อหาภายในโฟลเดอร์ `pos/`** ไว้ที่ root ของ repository (`netlify.toml` ต้องอยู่ที่ root) แล้วให้ Netlify Deploy; หน้าเว็บเผยแพร่จาก `public/` จากนั้นรีโหลดหน้าเว็บ
7. Owner ตรวจข้อมูลร้าน ตั้งขนาดกระดาษ วิธีคำนวณ VAT และเพดานส่วนลดในหน้า **ตั้งค่า**

ไฟล์ `public/js/config.js` ใช้ URL API เดิมของร้าน โคตร เทพ ตรวจให้ตรงกับ Apps Script ที่ Deploy ก่อนใช้งาน

### เมื่อขึ้นว่าเชื่อมต่อ Apps Script ไม่ได้

รุ่นนี้แก้หน้าเพิ่มสินค้า: ถ้าบันทึกสำเร็จแล้วแต่การโหลดรายการถัดไปสะดุด หน้าสินค้าจะแสดงรายการที่บันทึกทันทีและแจ้งว่าโหลดข้อมูลล่าสุดไม่สำเร็จ แทนการแจ้งว่าบันทึกไม่สำเร็จ หากการตอบกลับของคำสั่งบันทึกหาย ระบบจะตรวจ `request_id` ในชีต Products ก่อนแจ้งผล จึงต้องรัน `setupAll()` หนึ่งครั้งหลังอัปเดตเพื่อเพิ่มคอลัมน์ `request_id` โดยไม่ลบข้อมูลเดิม แล้ว Deploy Apps Script เป็นเวอร์ชันใหม่

ตรวจ `public/js/config.js` ว่าเป็น URL Web App ของร้านนี้ที่ลงท้าย `/exec` แล้วตรวจใน Apps Script ที่ **Deploy > Manage deployments** ว่า Web App ใช้เวอร์ชันล่าสุดและเปิดให้ผู้ใช้ POS เข้าถึงได้ หลังแก้ไฟล์เว็บ ต้องอัปโหลดหรือ push ไป GitHub และรอ Netlify เผยแพร่เวอร์ชันใหม่ด้วย การแก้ไฟล์ในเครื่องอย่างเดียวไม่เปลี่ยนเว็บที่ใช้อยู่

ถ้าเกิดเป็นบางครั้ง ให้เปิด Apps Script **Executions** เทียบเวลาเกิดปัญหา และดู Network ใน Developer Tools ของเบราว์เซอร์ หากคำสั่งบันทึกขายหรือซื้อแจ้งว่าตรวจผลไม่ได้ ให้ดูรายการล่าสุดก่อนกดซ้ำเพื่อป้องกันบิลซ้ำ หน้าเว็บจะลองคำสั่งอ่านข้อมูลซ้ำหนึ่งครั้งเมื่อการเชื่อมต่อล้มเหลว แต่จะไม่ส่งคำสั่งบันทึกซ้ำอัตโนมัติ

## วิธีใช้ใบเสนอราคา

เข้าเมนู **ใบเสนอราคา** เลือกลูกค้า สินค้า วันหมดอายุ และเลือกว่าจะจองสต็อกหรือไม่ ใบที่จองจะกันจำนวนสินค้าในระบบจนกว่าจะหมดอายุ ยกเลิก หรือยืนยันขาย เมื่อยืนยันขาย เลือก **ซื้อเชื่อ** เพื่อออกใบแจ้งหนี้ หรือเลือก **เงินสด/โอน** เพื่อออกใบเสร็จรับเงิน

การตั้ง VAT ในใบเสนอราคาจะถูกเก็บเป็นยอดของใบเสนอราคานั้น เมื่อยืนยันขาย ยอดจะยังตรงกับเอกสารที่เสนอแม้ร้านเปลี่ยนการตั้งค่า VAT ภายหลัง

## Backup, Archive และ Factory Reset

- **สำรองข้อมูลตอนนี้:** สร้างสำเนา Google Spreadsheet ในโฟลเดอร์ Backup ที่ `setupAll()` ตั้งไว้
- **Archive:** Owner เลือกวันตัด ยืนยันด้วยคำว่า `ARCHIVE` และ PIN ระบบสำรองทั้งไฟล์ก่อน แล้วลบเฉพาะบิลขาย/ซื้อที่ชำระครบและไม่มีเอกสารต่อเนื่องหลังวันตัด รวมถึงธุรกรรมเก่าที่ปิดแล้ว ระบบเก็บสินค้า ลูกค้า ผู้ขาย ล็อตสต็อกที่ยังเหลือ รายการที่ยังค้าง และข้อมูลบัญชีไว้
- **Factory Reset:** Owner ยืนยันด้วยคำว่า `RESET` และ PIN ระบบสำรองทั้งไฟล์ก่อนเคลียร์ข้อมูลทำงาน แล้วเก็บบัญชี Owner ปัจจุบันและประวัติไฟล์สำรองไว้
- ประวัติ Archive/Reset และลิงก์ไฟล์สำรองอยู่หน้า **ตั้งค่า** หากสถานะ `IN_PROGRESS` ค้าง ให้ตรวจไฟล์สำรองและข้อมูลในชีตก่อนทำรายการซ้ำ

Archive และ Reset เป็นงานที่กระทบข้อมูลจริง ควรทดลองกับสำเนา Spreadsheet ก่อนใช้กับร้านจริง โดยเฉพาะฐานข้อมูลที่มีการแก้ชีตด้วยมือ

## หมายเหตุเรื่องไฟล์ใน Drive

### แก้ล็อตยกมาซ้ำจาก SKU ที่ Google Sheets เก็บเป็นตัวเลข

หากหน้า Products แสดงคงเหลือแต่หน้า Stock ไม่มีล็อต หรือ `StockLots` มีแถว `LEGACY` ซ้ำ ให้แทนที่ไฟล์ Apps Script ด้วยไฟล์ใน ZIP นี้ แล้วรัน `repairDuplicateLegacyLots()` **หนึ่งครั้ง** จาก Apps Script editor ฟังก์ชันจะสร้างสำเนา Spreadsheet ใน Drive ก่อน แล้วปิดยอดคงเหลือเฉพาะล็อต `LEGACY` ที่เกินยอด `Products.qty_on_hand` โดยไม่เพิ่มหรือลดยอดสินค้าและไม่แก้ล็อตจากบิลซื้อ ลิงก์สำรองอยู่ใน Execution log หลังรัน จากนั้น Deploy Web App เป็นเวอร์ชันใหม่และรีเฟรชหน้า POS อย่ารัน `setupAll()` ของโค้ดรุ่นเก่าซ้ำ เพราะอาจสร้างล็อต `LEGACY` เพิ่ม

ตามคำสั่งสำหรับรุ่นนี้ ระบบยังคงตั้งสิทธิ์ใบเสร็จและสลิปเป็น “ทุกคนที่มีลิงก์ดูได้” เหมือนรุ่น 3.6 ผู้ถือ URL ของไฟล์จึงเปิดดูได้
